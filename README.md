# NikaS Water Accounting для Home Assistant

Специализированная панель **«Учёт воды»** для дома NikaS. Она объединяет давление питьевой и поливочной воды, текущие показания двух счётчиков Elehant, расход за выбранные периоды и диагностику источников.

Телеметрия работает на чтение. Вкладка «Настройки» позволяет администратору сохранять параметры расчёта и отметку о плановом отключении полива. Ручное обновление привязанных сущностей использует штатный `homeassistant.update_entity`. Обслуживание фильтров остаётся в отдельной «Водоподготовке».

## Что показано

- **Обзор** — два давления, накопительные показания и расход за 24 часа / 30 дней.
- **Расход** — питьевая вода, полив и сумма за 24 часа, 7 дней, 30 дней или 12 месяцев; данные берутся из Recorder.
- **Статистика** — дневные средние по типам дней РФ, текущий и предыдущий календарные месяцы, вода регенераций и проверяемая полнота данных.
- **Счётчики** — показания, температура, батарея, сигнал, время обновления каждого Elehant СВД-20, явные пороги давления и диагностика фактических сущностей.
- **Настройки** — начало выборки, порог низкого расхода, проверенный период регенераций и состояние линии полива с причиной/датой отключения.

[Методика статистики и порядок работы с настройками](docs/WATER_STATISTICS.md). Планово отключённый полив не вызывает предупреждений о нулевом давлении или отсутствии его телеметрии; отметка не управляет оборудованием и не заменяет пробелы истории нулями.

## Пороги давления

Пороги всегда видны на вкладке **«Счётчики»** под карточками двух счётчиков.

| Контур | Значение | Отображение |
| --- | ---: | --- |
| Питьевая вода | `0 бар` | красный — **Нет давления** |
| Питьевая вода | `2,4–3,1 бар`, включая границы | зелёный — **Норма** |
| Питьевая вода | любое другое числовое значение | оранжевый — **Отклонение** |
| Полив | `0 бар` | красный — **Нет давления** |
| Полив | `<0,3 бар`, кроме `0` | красный — **Аварийно низкое** |
| Полив | `0,3–<2,5 бар` | оранжевый — **Недостаточное** |
| Полив | `2,5–3,5 бар`, включая границы | зелёный — **Норма** |
| Полив | `>3,5–4,0 бар` | оранжевый — **Повышенное** |
| Полив | `>4,0 бар` | красный — **Аварийно высокое** |

Недоступное или нечисловое состояние показывается серым как **Нет данных** и не подменяется нулём.

## Привязанные сущности

| Назначение | Entity ID |
| --- | --- |
| Давление питьевой воды | `sensor.nikas_h2000_pro_pitevaia_voda` |
| Давление воды для полива | `sensor.nikas_h2000_pro_voda_na_poliv_2` |
| Связь ZONT | `binary_sensor.nikas_h2000_pro_online` |
| Счётчик питьевой воды | `sensor.schetchik_vody_svd_20_0020989_pokazaniia` |
| Счётчик полива | `sensor.schetchik_vody_svd_20_0020988_pokazaniia` |

Для каждого счётчика также используются его сущности `temperatura`, `batareia`, `signal` и `obnovleno`. Полная карта находится в [`const.py`](custom_components/water_accounting/const.py).

## Установка

1. Добавить репозиторий в HACS как пользовательский репозиторий категории **Integration**.
2. Установить **NikaS Water Accounting**.
3. Перезапустить Home Assistant.
4. Открыть `Настройки → Устройства и службы → Добавить интеграцию` и выбрать **NikaS Water Accounting**.
5. Открыть пункт **Учёт воды** в боковом меню.

Маршрут панели: `/dashboard-water`. Центральная плашка заголовка возвращает в объявленный родительский раздел; безопасный маршрут по умолчанию — `/home/overview`.

## Recorder и расход

Расход рассчитывается по долгосрочной статистике двух накопительных датчиков воды через аутентифицированный WebSocket Home Assistant. Для всех периодов запрашиваются часовые строки: готовые суточные и месячные сводки могут скрыть пропущенные часы.

Итог **«Всего»** известен только при полном покрытии запрошенных часов обоих счётчиков. Если часть данных отсутствует, показаны **Неполные данные**, прочерк вместо неполного итога и число подтверждённых часов каждого счётчика. При отсутствии подтверждённых часов показаны **Нет записей**. Реальный `change: 0` остаётся нулём. Для проверки первого часа запрашивается дополнительный предыдущий час; он не входит в расход. Час после разрыва также неизвестен: Recorder может вычислить его `change` относительно более старого показания. Пропуски, нечисловые/отрицательные значения и неоднозначные дубликаты не подменяются нулями или разностью накопительных показаний.

Периоды заканчиваются на границе последнего завершённого часа UTC. 24 часа — ровно 24 завершённых часа; 7/30 дней и начало 12-месячного окна отсчитываются по календарю браузера с округлением начала вверх до полного часа. Группы дней и месяцев на графике также используют время браузера, которое может отличаться от часового пояса сервера Home Assistant. Интервал графика без полного покрытия не рисуется как известный расход. Новейший час, который Recorder ещё не успел подготовить, остаётся пропуском, а не исключается из окна. Полнота относится к **часовым строкам Recorder**, не гарантирует непрерывность исходных измерений внутри часа.

Крайние календарные группы на графике включают только часы внутри выбранного окна: например, 7 дней от полудня могут затрагивать восемь календарных дат.

Запросы кэшируются отдельно для каждого периода, выполняются не более чем по два одновременно и завершаются ошибкой через 60 секунд вместо вечной загрузки. Для 12 месяцев требуется до примерно 8,8 тысячи часовых строк на счётчик плюс исходный час; дополнительных параллельных запросов нет.

## Разработка

```bash
node scripts/build.mjs
node scripts/check-panel.mjs
node scripts/check-statistics.mjs
node --test tests/*.test.mjs
node tests/water_ui_v22_harness.mjs
python scripts/check_nikas_ui_standard.py
python -m unittest discover -s tests -v
```

Production-файл `custom_components/water_accounting/frontend/water-accounting-panel.js` генерируется детерминированно из канонического Shell v2.1, zoom-контроллера, модели отчёта, интерфейса настроек, frontend-ядра и CSS. Во время работы панели нет runtime-импортов.

Браузерная приёмка с синтетическими данными: `node tests/statistics_settings_browser.mjs` (нужны Playwright и Chromium; путь к браузеру при необходимости задаётся через `WATER_BROWSER_EXECUTABLE`). Проверяются пять размеров экрана, пять вкладок, отключение/включение полива, задержанное сохранение, конфликт ревизии, черновик и права доступа.

## Совместимость интерфейса

Панель следует NikaS Specialized Panel UI Standard v2.2 и Navigation Contract v1.3: host-bound Shell v2.1, постоянные Header / рабочая область / нижние вкладки, gesture-only масштаб 75–200%, нативная прокрутка при 100%, capture-phase граничный scroll guard, стабильные DOM-поддеревья вкладок и возврат в объявленный родительский раздел.

## Водоподготовка вынесена отдельно

Начиная с **0.3.0-beta001** приложение отвечает за давление, показания водомеров, расход и диагностику. Фильтры, «Ёлка», соль, регенерации и GH находятся в [NikaS Water Treatment](https://github.com/NikaSir/ha-water-treatment).

[Порядок перехода и сохранения журналов](docs/WATER_SPLIT_MIGRATION.md). Существующие записи не удаляются при обновлении учёта; новый пакет переносит их один раз после передачи владения. Сначала обновляется учёт, затем устанавливается водоподготовка.
