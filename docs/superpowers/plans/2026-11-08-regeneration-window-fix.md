# Исправление beta003 после приёмки beta002

## Подтверждённые причины

- В рабочем HA причина и дата отключения полива сохранены, но `irrigation.enabled` остаётся `true`. Поэтому диагностика действует по включённой линии. Требуется ясный выбор состояния и заметное сохранение рядом с ним; прочие параметры пользователя сохраняются.
- 04.11 классифицируется как праздник, но день исключён из характерного среднего из-за отсутствующего `water_m3` в записи регенерации. UI ошибочно выглядит как отсутствие праздников в календаре.
- Пользователь задал новое правило: расход регенерации равен потреблению питьевой ветки с **02:30 до 04:30 Europe/Moscow в дату записанного цикла**.

## Реализация

1. Прикладная отметка полива: сверить текущую ревизию, изменить только `enabled=false`, сохранить через штатный API и проверить чтением. Для UI заменить неоднозначный флажок явным выбором «Включена / Отключена», показать применённое состояние и кнопку сохранения возле блока полива.
2. Новый read-only WS endpoint `water_accounting/regeneration_windows`: `{entity_id, dates}`. Для завершённых окон вернуть границы, показания и разность по Recorder; кешировать подтверждённые измерения в отдельном хранилище, чтобы очистка сырой истории не стирала уже рассчитанные объёмы. Не интерполировать почасовые данные; отсутствие, сброс или недоступность счётчика остаются неизвестными. Измерения привязаны к entity/date/window; журнал циклов в «Водоподготовке» не переписывается.
3. Отчёт берёт даты из журнала, получает окна и использует объём окна ровно один раз для цикла. Ручной `water_m3` другого интервала не выдаётся за измерение нового окна. Исходные дневные/месячные суммы не меняются.
4. Календарные группы показывают число календарных дат, число учтённых и причины исключений. 04.11 остаётся видимым праздником даже при неполном расходе.
5. Версия `0.3.0-beta003`, синтетические регрессии, браузерная приёмка, независимый review и отдельный PR. Не сливать новый PR без нового указания пользователя. В базу знаний записать новые границы, фактическую сверку и выполненные/непроверенные шаги.

## Проверки

- Неполное окно, `unknown` внутри, сброс счётчика, отсутствие начала, другой entity, конфликт/повтор даты, незавершённый сегодняшний день и окно.
- 04.11 при известном окне присутствует в праздничном среднем; при неизвестном явно показана исключённая праздничная дата.
- Отключение полива нейтрально, питьевые 2.0 бар остаются предупреждением. Ошибки чтения и незаписанный черновик не скрывают неисправности.
- Сохранённые ранее параметры и ревизия не перезаписываются по умолчанию.

## Результат реализации

- Даты циклов берутся исключительно из `settings.salt.history` интеграции «Водоподготовка»; это дополнительно подтверждено пользователем в ходе работы.
- Реализованы фиксированное окно Recorder, отдельное долговременное хранилище, явное состояние полива и видимые календарные исключения.
- Проверки: 72 теста JavaScript, 53 теста Python, 25 сочетаний вкладки/размера окна в Chromium; независимые review модели, интерфейса и backend завершены.
- При review устранён ложный ноль для выключенного Recorder/исключённой сущности. История запусков не восстанавливает прошлые ручные disable/enable внутри одного запуска; ограничение описано в методике.
- Проверка новой версии внутри рабочего Home Assistant, слияние и установка остаются отдельными шагами.
